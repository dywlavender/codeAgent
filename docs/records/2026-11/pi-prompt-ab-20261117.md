# Pi 提示词分层对照（2026-11-17）

分层候选将调查与证据规则放在行为段，把工程、资料状态和 System Guide 放在本轮上下文中。工具用途和返回边界由工具描述提供。这一分工参考 ZCode 的稳定行为约定与 DSH 的工具指导归属设计。 [ZCode System Prompt Contract](https://github.com/zai-org/ZCode/blob/main/apps/zcode-cli/docs/design/v2/loop/system-prompt-contract.md) · [DSH 提示词与工具指导归属](https://github.com/deepseek-ai/deepseek-harness/blob/master/.agents/notes/implemented/architecture/2026-07-05-prompt-variables-and-tool-guidance-ownership.zh.md)

## 实验设置

- 用生产 `QueryService` 和 Pi 1.5.0 执行，两组均请求 `deepseek/gpt-6-luna`，关闭 thinking。五道题每版运行三次，每次新会话，单次上限 300 秒。每题在奇数重复先跑现行组，偶数重复先跑候选组。
- 审批分发题使用 Apache Fineract 1.14.0，另外四题使用合成的渠道、中台和业务文档。综合贷款验证工程的输入未获自动审批允许发送给外部模型服务。 [Apache Fineract 1.14.0](https://github.com/apache/fineract/tree/1.14.0)
- 按题核对了两组的授权范围、实际资料状态和版本、工具名称及模式。AST 提款题采用 `ast`，术语题采用 `backbone`，其余采用 `none`。题干向两组提交相同文本，检查项与关键文件清单仅用于评测。
- 结果按答案正文和源文件逐项复核。Read 次数来自 Trace，模型的「目标覆盖」声明单独计数。原始 Trace、答案、用量、源码副本和复核文件保存在本机 `.data/evaluations/pi-prompt-ab-public-20261117/` 下。

## 结果

各对照值按「现行 / 候选」排列。模型、工具、Read 与 Token 取已完成运行的中位数。耗时为三次尝试的中位数，包含超时。

| 场景 | 完成 | 检查项通过＋部分 | Read | 模型调用 | 工具调用 | Token | 耗时（秒） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| HTTP 与 DTO | 3 / 3 | 11＋1 / 12＋0 | 4 / 3 | 6 / 4 | 8 / 7 | 42,001 / 26,966 | 58.23 / 28.45 |
| Fineract 命令分发 | 3 / 2 | 12＋0 / 8＋0 | 10 / 10.5 | 10 / 13 | 24 / 20.5 | 270,642 / 280,781 | 167.27 / 102.06 |
| AST 提款校验 | 3 / 3 | 9＋0 / 9＋0 | 2 / 2 | 5 / 5 | 5 / 7 | 36,083 / 34,607 | 29.33 / 69.24 |
| 业务术语 | 3 / 3 | 6＋0 / 6＋0 | 1 / 6 | 4 / 4 | 5 / 12 | 29,319 / 28,350 | 18.61 / 47.63 |
| 跨系统链路 | 3 / 3 | 10＋2 / 10＋2 | 9 / 8 | 4 / 5 | 14 / 17 | 30,765 / 36,528 | 36.27 / 43.86 |

- HTTP 题中，现行组有一轮遗漏报价保存。候选三轮均核对了校验、向上整除与保存，耗时和 Token 中位数均下降。
- Fineract 的五份答案均核实了审批 REST 分支、命令包装、注册查找和服务委托。候选第 2 轮在 300 秒时超时，Trace 已有 42 次工具调用和 20 次 Read。该轮的四项检查没有答卷可复核。 [公开 REST 入口源码](https://github.com/apache/fineract/blob/1.14.0/fineract-provider/src/main/java/org/apache/fineract/portfolio/loanaccount/api/LoansApiResource.java)
- AST 六轮均读取目标源码，答对两组条件。候选三轮均使用结构工具，其中两轮在目标 Read 前使用、一轮已读源码后才使用。现行组只有一轮使用结构工具，另外两轮靠文件工具找到源码。本例已读条件的正确率持平。
- 纯术语题六轮均引用了业务文档。候选每轮还读了中台源码。跨系统两组均有两项部分通过，缺口是报价保存或生成渠道编号与保存映射的顺序。
- 现行组 15 轮完成 51 项复核，48 项通过、3 项部分通过。候选 14 轮完成 47 项复核，45 项通过、2 项部分通过。现行组有 11 轮产生可解析的目标覆盖声明，候选的 14 份答案均省略。应以独立复核稿比较内容完整性。

## Trace 与发布判断

30 次均记录了 Pi 请求前报告的系统提示词。候选的生效文本按题缩短约 31%–39%。以归档的 AST 候选运行在 Chrome 验证了生效文本、装配片段和启用工具说明。Pi 附加的运行规则也在生效文本中可见，模型调用继续记录摘要。

目前保持现行提示词为在线默认。候选在 HTTP 题展示了效率收益，其余场景的成本和完成率表现混合。每类只有一道题，重复三次反映的是这些题的波动。公开仓库和合成示例的结果需与综合贷款工程的结果分列。
