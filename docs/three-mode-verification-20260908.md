## 必须处理的问题

### 1. 只导入问题与参考答案，可以执行一轮没有评分要点的实验

位置：`business_code_agent/evaluation/service.py:443`、`business_code_agent/evaluation/harness.py:112`、`frontend/src/pages/EvaluationPage.jsx:115`。

复现：导入仅包含 question/referenceAnswer 的JSON，checks为空；点击三组执行。三组都完成，三个初评记录均为completed且checks为空，最终qualityBlocks=0。系统没有误计为零分，这是正确的；但它仍消耗三次答题和三次评审，直到结果页才暴露无法比较质量。

建议：启动自动评分前列出缺少要点的案例，提供“生成并检查评分要点”入口，确认后再运行；或明确选择仅答题、不评分。不能让“自动初评”静默变成空评审。

### 2. AST更新后继续原对话会混用版本，历史答案也未记录所用版本

位置：`business_code_agent/query_agent/service.py:137`、`:274`。

复现：AST版本V1提问一次；修改源码并手动生成V2；继续同一AST对话。工作区换为V2，但runtime session参数从首次None变为旧session。重置条件只比较mode/scope，没有比较AST版本。查询结果与get_run未包含astVersionId。

影响：新版本资料与旧会话认知混在一起；旧回答无法确认当时使用哪版AST，与按版本引用、追溯实验的目标不一致。

建议：每次问答持久化资料版本；同模式下版本变化时新开模型会话，或固定旧会话使用原版本，并在页面明确版本。

### 3. 两组比较仍依赖第三组答题成功

位置：`business_code_agent/evaluation/runner.py:345`、`frontend/src/pages/EvaluationPage.jsx:178`。

复现：同一问题中无主干和有主干完成且有评分，AST答题失败。以三组汇总时pairs为空；仅用前两组调用相同汇总函数则得到1个有效配对。页面两组视图仅过滤三组汇总中的pairs，不能恢复被排除的样本。

影响：AST故障会让本来有效的“有主干 vs 无主干”结果消失，影响有效题数及优劣结论。

建议：三组总览可以用三组共同样本，各两组比较必须独立构造成本、评分配对集合。

### 4. “重试失败任务”实际会重新运行该题所有组，并读取当前题库和源码

位置：`business_code_agent/evaluation/service.py:566`。

代码核查：retry_failed只收集失败的caseId，然后调用start，保留原轮次数；start重新读取当前题库和源码，同时传入旧astVersionId。没有按失败的组别和轮次筛选，也没有复用原冻结输入。

影响：一组失败可能重复执行已经成功的两组；期间题库或源码变化后，新批次可能将新输入与旧AST混合。“重新跑这些题”与“重试原失败任务”语义不同。

建议：失败重试复用原冻结输入及准确的组别/轮次；若是按当前内容重跑，应明确命名并重新校验资料版本。

## 其他体验与统计注意点

- 逐项评分区域将模型初评与人工复核编辑器放在一起：模型判满足时，未填写的人工控件仍选“待核查”，应增加明确的“初评：满足/不满足”文字，区分结果和编辑状态。
- 三类质量指标当前通过评分要点中的关键词归类，并非独立维度评审；没有该类检查项时显示0也容易误解。建议题库显式保存要点类别，无适用项显示“未评估”。
- 本次只完成浏览器查看、AST手动生成，以及HTTP上传/执行链路；未声称完整浏览器文件选择器上传、真实外部模型答题或主干收益已验证。
