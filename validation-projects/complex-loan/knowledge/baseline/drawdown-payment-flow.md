# 提款支付流程（报价 → 受托支付 → 借据生效）

核对日期：2026-09-06。适用系统：渠道后端、贷款中台、外部模拟服务、Fineract。范围：受托支付单收款人；额度口径见[授信额度流程](credit-limit-flow.md)。

## 主要阶段

1. 可选条件查询：渠道按本渠道开放规则收窄中台产品（金额上限、期限、开关），收窄到不可用的产品不透出；渠道限制不会放大中台产品能力。
2. 报价：中台校验产品条件与额度，调 Fineract 试算，生成有有效期的报价快照；报价到提交期间条件变化必须重新校验，报价过期需重新试算。
3. 受理：中台校验并逐层预占额度 → 经 Fineract 创建借据 → 向外部模拟服务提交付款（业务单号幂等）。
4. 外部执行：模拟服务按场景配置返回同步终态，或受理中延迟回调；回调不送达时由中台补偿任务主动查单兜底。
5. 入账：付款成功后业务单进入"外部成功待入账"状态，中台完成 Fineract 放款登记（有防重复放款机制）→ 逐层预占转实占 → 业务单成功。
6. 失败与恢复：付款终态失败释放预占、业务单失败；入账失败转重试状态，由补偿任务继续，不重新付款、不判失败。
7. 展示：渠道把中台多个处理中状态合并展示为"处理中"，原始状态留痕可追踪。

关键关系：三个"成功"要分清——外部付款成功（模拟服务流水）、业务成功（中台账本）、展示成功（渠道合并状态），回答"为什么页面还在处理中"类问题必须先确认问的是哪一层。额度在受理时就已预占，这是"额度被占但钱没放"类问题的来源。

## 业务术语

- 预占/实占：见授信额度流程。
- 待入账：外部已付款成功、中台入账未完成的可恢复状态。
- 查单：中台主动向模拟服务查询终态，与回调走同一结果处理通道。
- 受托支付：付款给指定收款人（采购合同货款）；自主支付是后续计划。

## 覆盖边界

本流程覆盖到借据生效与额度实占。未覆盖：多收款人多批次、优惠券锁定、担保确认环节（阶段 4）；Fineract 借据层细节见原生流程文档。
