# Fineract 1.14.0 源码核查报告（能力清单与入口表）

核查日期：2026-09-06。核查方式：只读源码（Read/Grep），未构建、未运行。版本：Fineract `1.14.0`（7923d9e6）、Mifos X Web App `v1.0.0-fineract1.14`（eba51e08），见 `VERSIONS.md`。

本文回答一个问题：融商贷设计中点名的每项需求，Fineract 1.14.0 提供到什么程度。结论分三档：**复用**（原生能力直接使用）、**适配**（原生能力可配置承载，需少量粘合）、**扩展**（Fineract 没有，需在中台新建）。所有证据来自本仓库源码，路径以仓库根为基准。

## 1. 结论摘要

| 设计需求 | 判定 | 依据 |
| --- | --- | --- |
| 贷款账户生命周期（提交→审批→放款→结清） | 复用 | `LoanStatus`/`LoanEvent`/`DefaultLoanLifecycleStateMachine`，见入口表 |
| 每笔借款独立期限、还款方式 | 复用 | 每笔提款一个贷款账户；`AmortizationMethod`（`fineract-loan/.../loanproduct/domain/AmortizationMethod.java:22-24`） |
| 分批放款、每笔独立起息 | 复用 | `LoanDisbursementDetails`（`fineract-loan/.../loanaccount/domain/LoanDisbursementDetails.java:39-54`：expectedDisbursementDate/actualDisbursementDate/principal/netDisbursalAmount）；逐笔 `?command=disburse`+transactionAmount，每笔放款后重算计划（`LoanDisbursementService.java:123-167`） |
| 等额本金 / 等额本息 | 复用 | `AmortizationMethod.EQUAL_PRINCIPAL / EQUAL_INSTALLMENTS` |
| 按月付息到期还本 | **扩展** | 枚举只有两种摊销方式；无 bullet/balloon 产品（全库无相关产品字段） |
| 分段还本 | 适配（近似） | PROGRESSIVE + 产品级 `LoanProductVariableInstallmentConfig`（`LoanProduct.java:195,330`）支持可变分期，可作为近似承载，规则差异需在需求文档说明 |
| 降期供 / 缩短期限（提前还本后） | 复用 | `LoanRescheduleStrategyMethod`：`REDUCE_EMI_AMOUNT` / `REDUCE_NUMBER_OF_INSTALLMENTS` / `RESCHEDULE_NEXT_REPAYMENTS`（`fineract-loan/.../loanproduct/domain/LoanRescheduleStrategyMethod.java:36-41`），开启利息重算后生效（`AbstractCumulativeLoanScheduleGenerator.java:2674-2710`） |
| 节假日顺延 | 复用（注意默认行为） | `APPLY_HOLIDAYS_TO_LOANS` 任务只搬日期不重算利息（`ApplyHolidaysToLoansTasklet.java:99-186`）；顺延后利息是否重算取决于产品利息重算开关（`LoanInterestRecalculationCOBBusinessStep.java:41-53`） |
| 首期还款日、计息天数口径 | 复用 | `RepaymentStartDateType`（DISBURSEMENT_DATE/SUBMITTED_ON_DATE）；`DaysInYearType` Actual/360/364/365、`DaysInMonthType` Actual/30（`fineract-core/.../portfolio/common/domain/`） |
| 逾期容差 | 复用 | `inArrearsTolerance` 用于结清判定（`LoanWritePlatformServiceJpaRepositoryImpl.java:3307-3341`） |
| 提前结清试算 | 复用 | `calculatePrepaymentAmount`＝剩余本金＋截止日利息＋费用＋罚款，无优惠抵减（`AbstractCumulativeLoanScheduleGenerator.java:2791-2823`、`ProgressiveLoanScheduleGenerator.java:184-239`、`OutstandingAmountsDTO.java:28-47`）；提前终止走 `foreclosure` 命令 |
| 逾期识别与账龄 | 复用 | COB 日终批处理（Spring Batch，分区并行）：到期/逾期检查、账龄更新、逾期标签、逾期收费（`fineract-provider/.../cob/loan/` 各 BusinessStep）；另有 `UPDATE_LOAN_ARREARS_AGEING`、`UPDATE_NPA` 独立任务（`JobName.java:23-55`） |
| "冻结新提款" | **扩展** | `DelinquencyAction` 只有 `PAUSE`/`RESUME`（逾期标签控制），无冻结提款动作；冻结属中台额度台账职责 |
| 多级授信额度（总/子/集团/担保覆盖）、预占/占用/释放 | **扩展** | Fineract 无额度台账概念；中台新建，见边界设计 |
| 优惠（降息/免息/费用减免券） | **扩展** | 无优惠领域对象；且预提金额组成不含任何优惠抵减项，优惠只能在中台层实现并保留计算依据 |
| 担保机构覆盖额度、担保费、代偿 | **扩展** | 无担保机构领域对象；原生仅有借款担保人：`GuarantorType` CUSTOMER/STAFF/EXTERNAL，`GuarantorFunding*` 资金表仍在（`fineract-provider/.../guarantor/domain/`） |
| 渠道开放规则、字段转换、状态聚合 | **扩展** | 与 Fineract 无关，渠道后端新建 |
| 受托支付、多收款人、支付指令 | **扩展** | Fineract 只管贷款账户；支付编排在中台 |
| 异步回调、查单、补偿 | **扩展** | 命令处理同步（`SynchronousCommandProcessingService.java:147`）；无默认 HTTP 出站回调。可挂接点：业务事件（见 §4）、Spring Batch 自定义任务、可选 ActiveMQ 通知模块（`fineract-provider/.../notification/eventandlistener/ActiveMQNotificationEventPublisher.java`） |

## 2. 需要修正的设计假设

1. "按月付息到期还本"必须由中台扩展实现（或改用等额本金＋期末还本近似后明确标注差异），不能当作 Fineract 现成能力写进需求与题库。
2. "分段还本"如果指任意期次本金分段，`allowVariableInstallments`（渐进贷款）只能近似；如果接受"渐进贷款可变分期"语义则可用。阶段 2 前需定稿。
3. 节假日顺延默认不增加计息天数；要"顺延多计息"必须开启产品利息重算，并接受 COB 批量重算的时点行为。
4. "逾期→冻结新提款"不能靠 Fineract 的 delinquency 动作，冻结必须实现在中台额度台账，Fineract 只提供逾期事实（COB/账龄）。
5. 优惠不在 Fineract 的还款分配与预提计算内；优惠抵减要作为中台记录并保证与 Fineract 入账结果可核对，不能让两边各算一套利率。

## 4. 扩展挂接点（中台新增代码怎么接进 Fineract）

1. **同步业务事件**：实现 `BusinessEventListener<T>`，经 `BusinessEventNotifierService.addPostBusinessEventListener` 注册（放款成功、余额变更、拒绝等事件已有类型），用于驱动额度入账、渠道通知。
2. **日终任务**：在 `JobName` 增加自定义任务名并注册 Spring Batch tasklet/step（现有任务的注册模式在 `fineract-provider/.../jobs/` 各目录）。
3. **新 REST 入口**：仿 `LoansApiResource` 模式新增中台自有 API 资源，命令走 `CommandWrapperBuilder`＋`@CommandType`。
4. **新表**：Spring 数据访问与 Liquibase 变更集（`fineract-provider/src/main/resources/db/changelog/`）；轻量自定义字段可用 Datatables，不迁移核心表结构。
5. **装配**：参考 `LoanAccountAutoStarter`（`fineract-provider/.../loanaccount/starter/`）的条件化 Bean 装配模式。

## 5. 覆盖边界

本报告未核查：会计分录生成的完整规则、多租户/鉴权实现、报表模块、储蓄/存款细节、investor 模块。这些与本项目建设无直接冲突，进入对应阶段时再按需核查。核查结论适用于 `1.14.0` 标签；升级版本时需重新核对带行号的证据。
