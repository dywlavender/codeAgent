## 1. 系统构成与数据归属

**建设定位（2026-09-06 确认）**：本项目的核心用途是验证知识主干与智能体问答，代码是调查对象而非运行目标。阶段 2 起的代码建设以"规则真实、可调查、跨系统衔接可复现"为验收标准；不要求端到端运行验证，部署运行只在业务验收线需要时进行。中台采用**独立部署的旁挂服务（sidecar）**形态：Fineract 保持原版仓库不动（调查对象保持纯净），中台通过 Fineract REST 命令 API 调用贷款能力（`fineract-adapter`），不进程内扩展、不 fork Fineract 代码。理由：核查报告确认所需能力中"额度/优惠/担保/编排"本来就要新建，而 Fineract 原生命令 API 已覆盖借据生命周期；旁挂形态让每个仓库的职责与调查边界都更清晰。

| 系统 | 应用 | 建设方式 | 持有的数据（独立库，禁止跨库读取） |
| --- | --- | --- | --- |
| 渠道系统 | 渠道后端（loan-channel-service） | 新建（Spring Boot） | 渠道产品/金额/期限开放配置、渠道申请单、与中台业务单的关联映射、请求与结果摘要 |
| 渠道系统 | 客户业务前端（loan-channel-web） | 新增业务页面（Vue），运营管理复用 Mifos X（指向中台/Fineract API） | 无库 |
| 贷款中台系统 | 贷款中台（loan-middle） | 新建 Spring Boot 服务，经 Fineract REST API 使用贷款核算能力 | 业务申请、授信额度台账（预占/实占/释放明细）、合同与报价快照、优惠使用记录、担保责任、业务单与借据关联、入账状态 |
| 外部模拟系统 | 外部模拟服务（loan-external-simulator） | 新建（轻量 Spring Boot） | 模拟场景配置、审批/担保/付款/扣款的外部交易流水与执行状态、回调投递记录 |

借据、还款计划、还款分配明细由 Fineract 原生持有（m_loan 等核心表）；中台只保存业务单与借据的关联、以及自己职责内的台账与状态。原则回顾：中台是业务最终状态的唯一裁判；渠道只做准入、转换与聚合展示；模拟服务只模拟执行与结果。前端展示状态与内部状态的映射关系必须可追踪。

## 2. 标识链与幂等约定

```text
渠道申请号（channelRefNo）→ 中台业务单号（bizOrderNo）→ 外部执行流水号（extSerialNo）
```

- 一次客户提款申请（中台业务单）允许对应多条支付指令、多笔借据（tranche 放款批次）；一个渠道申请号对应一个中台业务单；一条支付指令对应一个外部流水号。
- 幂等键：中台→外部用业务单号+批次号；外部→中台回调用外部流水号+业务版本。重复回调不得重复生成借据、扣减优惠或恢复额度；已终态的指令收到重复结果只更新回调记录。
- 每个对象必须保存：当前状态、状态时间线、以及推动状态变化的外部流水号，保证"金额、状态、业务记录可相互核对"。

## 3. 状态机设计

### 提款申请（中台）

```text
待确认 → 处理中 → 部分成功/成功/失败
                ↘ 取消（仅终态前可取消）
```

- 处理中内部包含：资源锁定 → 担保确认 → 付款执行 → 入账登记。
- **"外部已付款成功、中台入账未完成"是显式可恢复状态**：此时禁止重新付款、禁止判定失败；后台任务（或补偿任务）继续完成 Fineract 放款登记，完成后转成功。该状态在列表与详情中可见。
- 部分成功＝多笔支付指令中部分成功；各成功批次按 Fineract tranche 机制分别登记实际放款日（`actualDisbursementDate`），渠道按总申请聚合展示。

### 外部付款/扣款（模拟服务）

```text
待提交 → 受理中 → 成功 | 失败 | 结果待确认（回调未送达，等待查单）
```

### 中台入账

```text
待处理 → 处理完成 | 待重试（附失败原因与重试次数）
```

### 优惠券（中台）

```text
可用 → 锁定（报价/申请期间）→ 已使用 | 释放 | 过期
```

### 担保责任（中台）

```text
待确认 → 有效 → 部分解除 → 解除
              ↘ 代偿处理中（外部确认后登记代偿与追偿关系）
```

## 4. 接口与异步衔接契约

四个方向的调用全部为 HTTP，不引入消息中间件（原则 6）：

| 方向 | 触发方式 | 契约要点 |
| --- | --- | --- |
| 渠道 → 中台 | 同步 REST | 渠道只传渠道语义字段；中台负责转换与校验产品支持性 |
| 中台 → 外部 | 同步 REST 提交 | 请求带幂等键与业务单号；返回受理或终态结果 |
| 外部 → 中台 | 异步 HTTP 回调 | 回调只携带外部流水号、结果、时间；中台验签、幂等处理后落库，**回调成功≠中台处理完成** |
| 中台 → 外部 | 查单（定时任务） | 对"受理中/结果待确认"超时的指令主动查单，把查单结果与回调走同一条入账通道 |

中台内部挂接 Fineract：

- 放款/还款用 Fineract 命令 API（同步命令、m_command_source 审计）；
- Fineract 业务事件（`LoanDisbursalBusinessEvent`、`LoanBalanceChangedBusinessEvent` 等）经 `BusinessEventNotifierService` 监听，用于更新额度台账与对外通知；
- 日终逾期事实来自 Fineract COB/账龄任务；"冻结新提款"由中台根据该事实操作自己的额度台账（Fineract `DelinquencyAction` 无此能力，见核查报告 §2）。

## 5. 中台扩展布局（loan-middle 独立服务内）

```text
channel-api/        渠道接入 API（授信查询、报价、提款、还款入口）
credit-limit/       授信与额度台账（预占/实占/释放、冻结）
drawdown-repay/     提款与还款编排（报价、申请、支付指令、入账状态机）
coupon-guarantee/   优惠与担保（阶段 4 落地，先留包位）
external-adapter/   外部模拟服务适配（提交、回调、查单）
fineract-adapter/   Fineract REST 适配（命令调用、账户查询；唯一允许触 Fineract 的模块）
compensation/       查单与补偿任务（定时：结果待确认查单、入账重试）
```

规则：fineract-adapter 是唯一允许调用 Fineract API 的模块；各模块独立建表（独立 Liquibase/DDL 脚本）；不修改 Fineract 仓库任何代码，确需核心行为差异时通过产品配置或外层编排解决并记录决策。

## 6. 职责归属判例（写测试与题库时引用）

| 场景 | 判定 |
| --- | --- |
| 渠道限制某产品 12 期 | 渠道配置行为；中台只校验产品本身支持 12 期 |
| 外部审批返回额度 | 只是数据；额度生效、预占、占用、释放由中台台账完成 |
| 外部支付成功 | 不等于放款；中台确认最终结果后调 Fineract 完成放款登记 |
| 模拟服务回调成功 | 只代表外部环节完成；中台入账状态另查 |
| 担保费率（"担保利率"） | 统一解释为担保费率，业务别名与历史字段映射只在需求文档与主干登记 |
| 客户换渠道入口 | 可选条件不同由渠道配置决定，中台产品规则相同 |
| 归还利息/费用 | 不恢复本金授信额度（中台规则） |
| 授信过期/冻结 | 减占用可以，重新获得提款资格不行（中台规则） |
