# 阶段 2 接口契约（字段级）

定稿日期：2026-09-06。依据：[三系统边界设计](三系统边界设计.md) §2-§4。阶段 2 范围：授信已生效（种子额度）、受托支付单收款人、无优惠/担保；多收款人、优惠、担保在阶段 4 扩展本契约。本文是三个后端实现的共同规范，字段名与状态值必须逐字一致。

## 1. 标识与通用约定

- 标识链：`channelRefNo`（CHN-开头，渠道生成）→ `bizOrderNo`（DD-提款 / RP-还款 / CR-授信，中台生成）→ `extSerialNo`（EXT-开头，模拟服务生成）。
- 幂等键：中台→外部提交带 `bizOrderNo`；外部→中台回调用 `extSerialNo` + `bizOrderNo`。同一幂等键重复请求返回首次结果，不产生新业务记录。
- 金额单位：元，两位小数；期限单位：月。所有接口 JSON，UTF-8。
- 时间：ISO-8601 字符串（`2026-09-06T10:00:00`）。

## 2. 状态枚举（跨系统对齐）

### 提款申请 bizOrder（中台持有）

| 状态 | 含义 |
| --- | --- |
| PROCESSING | 已锁定额度并提交付款，处理中 |
| EXTERNAL_SUCCESS_BOOKING_PENDING | 外部付款已成功，中台入账（Fineract 放款登记）未完成——可恢复状态，禁止重付、禁止判失败 |
| SUCCESS | 入账完成，借据生效 |
| FAILED | 终态失败（付款失败且额度已释放） |
| CANCELLED | 提交前取消 |

对外（渠道）聚合展示：`PROCESSING/EXTERNAL_SUCCESS_BOOKING_PENDING/RETRY_NEEDED` 统一展示为"处理中"，映射关系由渠道保存，详情保留中台原始状态。

### 外部付款指令 extTransaction（模拟服务持有）

`TO_SUBMIT → PROCESSING → SUCCESS | FAILED | RESULT_UNCONFIRMED`（RESULT_UNCONFIRMED＝异步结果已产生但回调未送达，等待查单）。

### 中台入账 booking（中台持有）

`TO_BOOK → BOOKED | RETRY_NEEDED`（RETRY_NEEDED 附失败原因与重试次数，补偿任务重试）。

### 还款订单（中台持有）

`PROCESSING → SUCCESS | FAILED`；外部扣款状态同外部付款指令。

## 3. 中台 ↔ 外部模拟服务

### 提交付款

`POST {simulator}/sim/api/v1/payments`

```json
请求 { "bizOrderNo": "DD-202609060001", "payeeName": "供应商甲", "payeeAccount": "622200001", "amount": 300000.00 }
响应 200 { "extSerialNo": "EXT-P0001", "status": "PROCESSING" }        // 受理
     或 200 { "extSerialNo": "EXT-P0002", "status": "SUCCESS" }        // 同步成功
     或 200 { "extSerialNo": "EXT-P0003", "status": "REJECTED" }       // 同步拒绝（终态，等同 FAILED）
```

### 查付款结果

`GET {simulator}/sim/api/v1/payments/{extSerialNo}` → `{ "extSerialNo": "...", "status": "SUCCESS|FAILED|PROCESSING|RESULT_UNCONFIRMED", "finishedAt": null }`

### 提交扣款（还款）

`POST {simulator}/sim/api/v1/deductions`，请求 `{ "bizOrderNo": "RP-...", "payerAccount": "...", "amount": 45230.55 }`；响应与付款相同（extSerialNo 走 EXT-D 前缀）。查扣款：`GET /sim/api/v1/deductions/{extSerialNo}`。

### 回调（模拟服务 → 中台）

`POST {middle}/middle/api/v1/callbacks/external-result`

```json
{ "type": "PAYMENT|DEDUCTION", "extSerialNo": "EXT-P0001", "bizOrderNo": "DD-202609060001",
  "result": "SUCCESS|FAILED", "finishedAt": "..." }
```

中台处理规则：验 bizOrderNo+extSerialNo 存在且匹配；幂等（已终态直接 200 幂等确认，不产生新记录）；PAYMENT→提款入账流程，DEDUCTION→还款入账流程。响应 `{ "received": true }`。

### 场景配置（模拟服务）

`PUT {simulator}/sim/api/v1/scenarios/{bizOrderNo}`，body `{ "scenario": "SYNC_SUCCESS|SYNC_REJECT|ASYNC_SUCCESS_DELAY|ASYNC_FAIL|NO_CALLBACK_NEED_QUERY", "delaySeconds": 2 }`；未配置的 bizOrderNo 走默认 `SYNC_SUCCESS`。场景数据不得混入正式业务字段（边界设计 §7）。

## 4. 渠道后端 ↔ 中台

### 可选条件查询（渠道过滤后透出）

`GET {middle}/middle/api/v1/drawdowns/options?creditId=CR-...` →
```json
{ "creditId": "CR-...", "products": [ { "productId": "LOAN-PURCHASE", "productName": "采购贷",
  "minAmount": 50000, "maxAmount": 1000000, "terms": [3, 6, 12],
  "repaymentModes": ["EQUAL_PRINCIPAL", "EQUAL_INSTALLMENTS"],
  "availableAmount": 500000.00 } ] }
```
`availableAmount`＝总授信上限−实占−预占（阶段 2 单层额度；阶段 3 起返回各层余量明细）。

### 报价试算

`POST {middle}/middle/api/v1/drawdowns/quote`
```json
请求 { "creditId": "CR-...", "productId": "LOAN-PURCHASE", "amount": 500000.00, "termMonths": 12, "repaymentMode": "EQUAL_PRINCIPAL", "firstRepaymentDate": "2026-10-20" }
响应 { "quoteNo": "QT-...", "annualInterestRate": 8.00, "totalInterest": 21666.67,
       "trialSchedule": [ { "period": 1, "dueDate": "2026-10-20", "principal": 41666.67, "interest": 3333.33 } ], "validUntil": "..." }
```

### 提款申请

`POST {middle}/middle/api/v1/drawdowns`
```json
{ "quoteNo": "QT-...", "payeeName": "供应商甲", "payeeAccount": "622200001", "purpose": "采购合同货款" }
响应 202 { "bizOrderNo": "DD-202609060001", "status": "PROCESSING" }
```
校验失败返回 4xx＋错误码（QUOTE_EXPIRED / AMOUNT_CHANGED_NEED_REQUOTE / LIMIT_INSUFFICIENT / TERM_NOT_SUPPORTED）。

### 提款结果

`GET {middle}/middle/api/v1/drawdowns/{bizOrderNo}` →
```json
{ "bizOrderNo": "DD-...", "status": "SUCCESS", "amount": 500000.00,
  "payments": [ { "extSerialNo": "EXT-P0001", "status": "SUCCESS", "amount": 500000.00 } ],
  "booking": { "status": "BOOKED", "loanAccountNo": "1", "retryCount": 0 } }
```

### 还款试算与申请

`POST {middle}/middle/api/v1/repayments/prepayment-quote`（提前结清/部分还本试算）请求 `{ "loanAccountNo": "1", "type": "EARLY_SETTLE|EARLY_PRINCIPAL", "amount": 100000.00 }`；
`POST {middle}/middle/api/v1/repayments` 请求 `{ "loanAccountNo": "1", "payerAccount": "...", "type": "DUE|EARLY_PRINCIPAL|EARLY_SETTLE", "amount": 45230.55 }` → 202 `{ "bizOrderNo": "RP-...", "status": "PROCESSING" }`；查询 `GET {middle}/middle/api/v1/repayments/{bizOrderNo}` 结构同提款结果（含 `allocation`：本金/利息/费用分配明细）。

### 额度恢复规则（中台实现，写进测试）

还款入账成功后：按分配明细中的**本金部分**恢复授信占用；利息、费用不恢复。预占仅存在于提款流程，还款无预占。

## 5. 客户前端 ↔ 渠道后端

`GET /api/drawdown/options`、`POST /api/drawdowns`、`GET /api/drawdowns/{channelRefNo}`、`POST /api/repayments`、`GET /api/repayments/{channelRefNo}`。渠道负责：渠道开放条件过滤（企业自助渠道单笔上限 30 万、期限仅 3/6/12）、字段转换、channelRefNo 生成与映射保存、状态聚合展示。

## 6. 中台内部关键流转（阶段 2 提款主链路）

```text
报价校验 → 额度预占(PRE_OCCUPY) → 创建借据(Fineract POST /loans，product 映射) 
→ 提交付款(simulator) → 回调/查单成功 → 入账(Fineract ?command=disburse) 
→ 额度实占(释放预占、登记实占) → SUCCESS
任一环失败/超时：补偿任务查单；付款终态失败 → 释放预占 → FAILED
"外部成功+入账未完成"：状态停在 EXTERNAL_SUCCESS_BOOKING_PENDING，补偿任务重试入账
```
