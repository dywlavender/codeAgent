# Code Atlas 前端重设计方案

日期：2026-09-10。状态：设计提案，尚未替换现有前端。

## 设计判断

目标是面向日常代码与业务调查的简洁工作台，借鉴 Codex 的任务侧栏、单列对话与按需展开方式。保留 Code Atlas 名称和现有能力，统一页面组织和视觉规则。

本次查看了本地运行页面的首页、已有问答、项目资料和效果验证，并核对 App、主题、样式及 AST 页面源码。判断依据是当前项目界面；本方案不声称逐像素复刻某个版本的 Codex。

现有首页已经有合理的留白与居中输入框，可以延续。主要问题是控件密度、信息优先级和跨页不一致，不能只靠缩小字号或换灰色解决。

## 现状问题

| 已观察到的现状 | 影响 | 调整 |
| --- | --- | --- |
| 侧栏并列问答、项目资料、知识图谱、效果验证、AST 管理和业务补充知识维护，最近会话位于它们下方 | 日常任务被低频管理入口挤压 | 新对话与最近会话占主体；底部保留项目资料、效果验证及工程设置 |
| 输入框工具栏同时展示工程、仓库数、模型、三模式、资料版本、只读提示和快捷键；当前宽度下“Enter 发送”换行 | 提问前需要辨认太多控制项 | 保留调查范围、资料模式和发送；模型以次要文字出现，版本与说明进入模式详情 |
| 工程名在侧栏、顶栏和输入框中重复 | 重复信息占据有效空间 | 工程选择放在侧栏；顶栏显示当前任务或页面名；输入框只显示调查范围 |
| 回答前铺开多个读取文件卡片 | 读者需要越过证据目录才能看到结论 | 回答优先；过程压成一行，实际引用放在正文附近，完整来源按需展开 |
| 资料页每个来源重复显示类型、授权标签、完整路径和说明 | 扫描困难，技术细节成为页面主体 | 一行一个来源，仅显示名称、类型与可用状态；点击查看路径、授权和依据 |
| 主对话白底、资料页暖色、评测页中性灰，标题大小也不同 | 页面像不同阶段拼接的产品 | 全站统一背景、顶栏、标题和列表规则 |

代码侧的原因也可定位：`main.jsx` 只引入 `styles.css`；`theme.js` 使用暖色，`styles.css` 又包含局部灰白覆盖；独立的 `design-tokens.css` 没有被入口引入。后续应收敛为一个实际生效的主题来源。

## 推荐信息架构

```text
Code Atlas                         当前任务 / 页面标题
当前工程 ▾                         主工作区

＋ 新对话

最近会话
  提款申请在哪里校验？
  梳理提款申请流程
  …

项目资料
效果验证
工程设置
```

默认只有侧栏和主工作区两列。右侧详情仅在打开引用、文件或记录时出现，可关闭；不能成为常驻第三列。

- **项目资料**：资料来源、AST 管理、知识图谱三个局部入口。资料来源仍区分源码、需求原文、业务补充知识、自动代码地图；旧业务基线显示为兼容来源。业务知识的编辑操作放在相应资料详情中，沿用管理员权限。
- **效果验证**：历史批次作为默认页，顶部提供“新建实验”和“测试案例”。新建表单与批次详情分别展示，不把创建、进度、评分和题库编辑全部堆在一个画面。
- **工程设置**：工程配置、目录及管理员会话。工程登记收进工程选择菜单。
- 实施时保留已有 `#/agent`、`#/library`、`#/graph`、`#/evaluation`、`#/ast`、`#/admin` 深链接，通过新的导航分组承接，不需要同步改变后端 API。

## 关键页面

### 新对话

标题“今天想弄清楚什么？”，下方一个输入框。删去首页资料原理说明、重复警示和大段引导；保留两个简短问题示例，首次使用时展示。

输入框底部左侧为“全部仓库”与“业务补充”两个紧凑选择器，右侧为发送。模型名仅出现一次，不为单个可用模型制造选择器。

“基础资料 / 业务补充 / AST 结构”是建议采用的展示名称；分别映射现有无主干、有主干、AST 模式，不改变资料边界。展开菜单后说明差别及实际版本。历史批次保留原始模式名称，不能因视觉改造重写历史实验语义。

### 对话中

顶栏展示任务标题；正文保持单列、舒适行宽。用户问题用浅灰气泡，回答直接排版，不套大卡片。

运行中显示一行当前动作及停止按钮；完成后将过程默认收起。正文引用可以打开侧面详情，完整文件目录放在“查看来源”中。“已读取文件”与“支持此结论的引用”必须区分。

底部固定续问输入框。长答案只滚动正文；侧栏与输入框保持位置。失败时在对应轮次显示简短原因和重试入口，停止后显示“已停止”，避免全页警报。

### 项目资料

使用紧凑列表：名称、类别、状态。一处搜索和类别筛选即可，路径、读取权限和长说明进入详情。异常状态保留文字标识与可执行入口。

AST 页突出当前版本、更新时间、覆盖范围，以及明确的“生成 AST / 重新生成”操作；规则说明折叠。知识图谱保留独立画布工作区，进入后才加载展示，不作为默认首页装饰。

### 效果验证

历史列表默认展示批次名称、状态、题目数量和时间。新建实验采用单列设置：题库、执行范围、对照协议；重复次数和自动初评放在进阶设置。提交前显示所选组别、资料是否就绪及预计执行次数。

批次详情先显示一句可核查结论，再显示逐题列表。点击某题进入对照详情；仅在这个层级使用双列答案。模型初评与人工复核始终区分，失败题和未配对题不混入有效对照结论。

三模式和五组对照均按记录的协议呈现；三模式需要明确 AST 版本，五组方案按其资料要求检查，不能用视觉统一改变实验条件。

## 视觉规则

| 项目 | 建议 |
| --- | --- |
| 色彩 | 浅色以白色主区、浅灰侧栏、深灰文字为主；深色使用对应中性色；现有青绿仅小面积用于链接或状态 |
| 侧栏 | 桌面默认 224px，可收起；会话以单行标题为主，失败和运行状态才持续突出 |
| 顶栏 | 全页统一约 52px，标题 14px；管理页内容标题 22px，避免重复的栏目小标题 |
| 内容宽度 | 对话约 720–800px；资料和评测列表约 960px；证据面板约 360px |
| 字体 | 系统无衬线与苹方；主界面 14px，回答 15–16px，次要文字 12–13px |
| 圆角 | 控件 8px，输入框 16px，气泡 16px；减少胶囊和重复外框 |
| 边界 | 主要用留白和细分隔线；列表行无阴影，仅浮层保留轻阴影 |
| 动效 | 120–160ms 的状态切换；尊重减少动画设置 |

窄屏下先收起侧栏，随后将证据详情改为覆盖面板。输入框控制项允许有序换行，不能缩成小字；逐题对照在宽度不足时改为上下排列。实现后检查 1440、1024、768、390px。

## 实施顺序与验收

1. 统一实际生效的主题变量、基础控件和应用外框，移除互相覆盖的旧布局规则。
2. 完成侧栏及新对话／续问布局，保留滚动、流式输出、停止和会话恢复行为。
3. 统一资料、AST、图谱与知识维护的导航层级，再改造评测列表和详情。
4. 验证真实长回答、多会话、资料异常、实验运行／完成状态及窄屏布局；沿用已有功能测试，针对改动补充必要交互验证。

验收重点：进入首页无需先理解实验术语即可提问；正文前没有成排证据卡；所有页面使用同一外框；高频任务可直接继续；低频操作可找到；文本与控制项不挤压换行错位。

工程切换仍通过 ProjectContext 归属，不跨工程续用会话和版本；工程登记只创建边界；AST 始终由用户手动生成。此提案遵循 2026-09-08 知识体系方向，不改变业务知识、代码地图和源码证据的职责。
