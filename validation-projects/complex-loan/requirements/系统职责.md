# 系统职责说明

版本：V1 阶段 2（三系统代码基座）。源码版本固定记录见项目目录 `VERSIONS.md`（Fineract `1.14.0`、Mifos X Web App `v1.0.0-fineract1.14`）。融商贷三个自研应用的源码为本项目随附源码，无上游版本。

## 系统构成

项目名**融商贷——小微企业经营贷款平台**，用于企业经营周转和采购付款融资：一份授信下可多次提款，每笔借款独立选择期限、还款方式与支付路径。登记四个系统、五个应用：

| 系统 | 应用 | 建设方式 | 持有的数据 |
| --- | --- | --- | --- |
| 渠道系统 | 融商贷渠道后端（channel-service） | 自研 | 渠道产品开放规则、渠道申请单、`channelRefNo → bizOrderNo` 映射、展示状态 |
| 贷款中台系统 | 融商贷贷款中台（loan-middle） | 自研（旁挂服务） | 授信额度台账（预占/实占/释放流水）、产品配置、报价快照、提款业务单、还款订单、入账状态 |
| 贷款中台系统 | Fineract 贷款中台服务（fineract-backend） | 原版 Fineract 1.14.0，不修改 | 借据（m_loan）、还款计划、还款交易与分配、会计 |
| 外部模拟系统 | 外部系统模拟服务（external-simulator） | 自研 | 场景配置、外部交易流水（付款/扣款）、回调投递记录 |
| Fineract 开源贷款平台 | Mifos X 平台 Web 前端（mifos-web） | 原版，运营页面复用 | 无库 |

另有客户业务前端（Vue）规划中，尚未建库；当前调查以三个后端与 Fineract 为主。

## 关键架构决策

- **中台是旁挂服务（sidecar）**：Fineract 保持原版不动，中台通过 Fineract REST 命令 API（`/fineract-provider/api/v1`）创建借据、放款、入账；`fineract-adapter` 是中台唯一允许触 Fineract 的模块。
- **中台是业务最终状态的唯一裁判**：额度生效、预占/占用/释放、入账状态、报价快照由中台管理；外部服务返回的"成功"只是数据，不等于业务完成。
- **异步链路不引入消息中间件**：提交（同步 REST）＋回调（外部→中台 HTTP）＋查单/补偿（中台定时任务）。
- **各系统独立数据存储**（H2/独立库），禁止跨库读取，全部经接口。

## 各应用职责边界

- **渠道后端**：渠道产品开放规则（金额上限、期限、开关）、字段转换、申请入口、`channelRefNo` 生成与映射、展示状态聚合（中台多个内部状态对外可合并为"处理中"，但保留原始状态）。渠道不做业务规则校验，只做渠道规则。
- **贷款中台**：产品条件与报价、额度预占/实占/释放、提款编排（含"外部已付款成功、中台入账未完成"可恢复状态）、还款编排与分配结果保存、补偿查单。
- **Fineract**：贷款账户生命周期、还款计划生成与重算、还款金额在费用/罚息/利息/本金上的分配、结清状态判定。中台不重复实现分配算法。
- **外部模拟服务**：按场景配置模拟付款/扣款执行结果（同步成功/同步拒绝/延迟回调/回调不送达），只回放结果，不做业务判断。

## 调查注意

- 已实现（阶段 2/3）：三系统提款还款链路、多层额度台账（总授信/产品子额度/集团限额/担保覆盖）、授信申请与提额降额审批、冻结/解冻、产品版本快照。
- 优惠券、担保责任生命周期（担保申请/确认/代偿/解除）、多收款人多批次属于阶段 4 计划，**当前代码中不存在**；客户业务前端（Vue）尚未建库。调查结论不得把它们当成已实现。
- 阶段 2 主链路：报价 → 提款申请（逐层预占＋建借据＋受托支付单收款人）→ 外部付款 → 中台入账（Fineract 放款）→ 逐层实占；还款：订单 → 扣款 → Fineract 入账 → 按本金部分逐层恢复额度。
