# 业务基线使用指南

业务基线是给 Agent 的少量关键业务事实，不是完整业务说明书。目标是用少量稳定信息帮助 Agent 理解业务，并在需要时从当前代码开始调查。

## 推荐内容

### 业务术语

```markdown
## 极优

极优是再担保类型产品，代码中一般用 JY 表示。
```

### 系统边界

```markdown
## 贷款中台系统

贷款中台负责提款、授信和还款的业务编排，不负责核心账务处理。
```

### 业务能力

```markdown
## 提款结果处理能力

贷款中台获取提款最终结果，并根据产品类型执行提款后处理。
```

### 粗粒度流程

```markdown
## 提款主流程

1. 渠道接收提款申请。
2. 中台进行提款业务编排。
3. 信贷处理提款。
4. 核心完成放款。
5. 中台同步提款结果。
```

### 可选调查入口

只有 `FLOW` / `CAPABILITY` 需要时才补入口。入口是导航提示，不是实现说明；每个应用可以有多个入口。

```markdown
## 提款申请流程

用户在渠道发起提款，中台完成申请处理。

### 调查入口

- 提款 H5 | PAGE | WithdrawApply.vue
- 渠道服务 | CONTROLLER | ChannelWithdrawController
- 贷款中台 | CONTROLLER | MiddleWithdrawController
```

支持的入口类型：`PAGE`、`CONTROLLER`、`JOB`、`CONSUMER`、`ENTRY_CLASS`、`OTHER`。应用名称或 id 必须在项目配置中存在；入口名称只能是页面名、类名、Job 或 Consumer 名，不能是限定类名、方法、路径或行号。入口名称和类型必须在同一 Markdown 小节原文中逐字出现。

### 业务关系

```markdown
## 担保产品提款后处理

担保类产品提款成功后，会触发担保处理并产生担保文件。
```

### 独立规则

```markdown
## 担保产品提款规则

产品属于需要担保的产品时，提款成功后必须进入担保处理。
```

## 不需要填写

- JSON 或 YAML；
- 完整包名和文件路径（入口只写短名称）；
- 方法调用链；
- SQL 和数据库字段；
- 可以直接从代码索引得到的技术细节；
- 不确定的推测。

## 提升调查效果

如果业务名称和代码命名差异很大，可以在自然语言中补充真实业务别名；如果已经知道稳定的页面或入口类，再补一条 Entry Anchor：

```text
极优在代码中一般用 JY 表示。
提款结果处理相关业务通常称为 WithdrawResult。
```

不要补方法名、调用链或实现类。Agent 解析入口后会基于当前代码实时读取这些细节；入口失效时会报告解析状态并停止该入口分支，不会自动扩大为全局代码搜索。

## 内容规模

一份基线可以描述一个业务域，不要求一功能一文件。优先补充：

1. 项目特有名词；
2. 关键跨系统关系；
3. 容易从代码误解的业务规则；
4. 代码命名与业务叫法之间的别名；
5. 少量稳定的 FLOW/CAPABILITY 调查入口。

重复的技术过程和临时问题结论不要写入基线。
