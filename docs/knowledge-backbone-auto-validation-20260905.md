结论：已完成可配置题库、成对答题、源码模型初评、自动报告及复核覆盖流程。当前演示题目仍未证明知识主干有稳定增益；模型评分本身也不能直接当作可信验收结论。

三个现有提款演示仓库，4 道已知问题，各运行有主干／无主干一次，共 8 次真实答题。两组保留相同原始代码和 README；有主干组额外提供项目总览及按需业务文档。使用本地 Claude Code 及现有网关。

有主干的流程题区分字段检查与实际完成更清楚，但前置条件题漏掉银行卡和还款参数检查；无主干的流程题则在结尾错误声称真实签约顺序被代码强制。两组优惠券核心调用链和固定列表结论均正确，有些附加说明不准确。边界题均确认当前仓库没有真实放款实现。

额外问题条数不等于错误严重程度，也不能抵消检查项遗漏。每题只有一次，耗时和调用次数的变化不能解释为稳定收益。当前问题是已知回归题，复杂项目与新问题的效果未验证。

## 自动评分的实测问题

第一轮 8 次模型评审中发现：缺少主干参考文档导致真实引用被误判；把“无问题”写进 issues；只因源码存在某个检查就给漏答的候选答案加分；忽略候选答案内部矛盾。

修正后，两组评分者均能读取相同的全部参考文档，要求得分项引用候选原文及源码，随后对同一批答案重评 8 次，没有重复答题。最终解析器允许 JSON 代码块、Markdown 样式和空白差异及省略号分隔引文。5/8 份重评通过格式与引文校验，3/8 仍有改写引文等问题，保留为评分失败，不按零分处理。通过校验的评分仍有漏判矛盾，因此最终质量表使用执行助手逐项复核记录，并非独立人工盲评。

本轮总调用为 8 次答题＋16 次评审；答题成本表不含评审。CLI 和响应分别报告 `claude-opus-4-8[1m]` 与 `glm-5.3`，上游真实模型未独立核实。

当前适合自动采集、比较和生成评审初稿，不适合无人复核地判定“主干有效”。不继续为同一演示题反复调评分器，以免把已知题调成看似稳定的成绩。
