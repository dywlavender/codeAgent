# 知识主干两层改写与回归验证

日期：2026-09-05。依据：[整改方向](knowledge-backbone-direction.md)与[改写前核查](knowledge-backbone-validation-20260905.md)。

## 本轮结论

两层文档与总览接入已完成，12项自动回归通过，24次真实模型调用均取得答案，无采集异常或补测。新版在部分事实表达上更清楚，本轮耗时低于旧版，但总体调查效率仍未优于无主干。复杂项目上的效果继续作为待验证假设。

## 改动内容

当前业务基线组织为两层：

- [`project-overview.md`](../knowledge/baseline/project-overview.md)：项目范围、系统／应用职责、入口、业务目录与覆盖边界，约一页。
- [`withdraw-flow.md`](../knowledge/baseline/withdraw-flow.md)：三阶段九步业务流、职责及阶段关系、业务用词与当前检索词、调查入口和未覆盖环节。

业务顺序沿用原人工基线，系统职责与用词对应根据当前项目配置、三个仓库 README、页面与接口声明核对。没有编造历史别名、核心放款或异步消息链路，也没有将前次评测的字段校验答案、固定 ID 或金额筛选结论抄入主干。

总览现在通过 Runtime 每轮追加到提示中，包括续聊；其正文不重复写入生成的 `CLAUDE.md`。具体流程文件继续按需读取，不增加固定检索步骤或 Python 图谱查询。没有约定总览文件的项目继续使用原有资料搜索方式。

已有常驻服务需要重启一次加载这次 Python 改动；之后总览文件内容会在每轮读取，无需为每次文档修改重启服务。

这次改写改善了已有业务范围内的整体认识与调查参照，但演示项目没有真实跨系统异步后半程，文档只能明确尚未登记的范围，不能因此宣称已经建成覆盖真实贷款全生命周期的主干。

## 复杂项目的作用假设

知识主干更可能在业务叫法与代码命名不同、系统职责容易混淆、存在跨仓库异步衔接和多个业务分支时提供增益。仓库多或代码长本身不构成收益证明：若模型仍能快速通过现有资料定位，新增地图的边际收益可能很小。

复杂度也会增加知识维护和上下文负担，因此采用简短总览与按需业务流，而非把所有知识全部注入。后续应按实际调查困难选择真实历史问题，同时保留普通代码题，观察复杂题的改善是否以普通题的额外成本为代价。

## 验证方法

1. 自动回归覆盖 `test_agent_workspace.py` 与 `test_claude_runtime.py`，共12项通过。新增验证总览在首次问答和续聊使用当前版本、流程正文不会随总览一起注入；保留运行时和目录授权相关验证。
2. 真实模型比较三组：无主干但保留 README；冻结的旧21行主干；新版总览自动提供且业务流程按需读取。
3. 沿用前次4题与每题5个检查点，每组每题2次，共24次；新旧组使用相同源码和README，独立临时工作区、新会话，两路并发。
4. 旧主干来自前次评测冻结资料，不覆盖前次结果。问题、运行顺序和所有输入在调用前保存。人工逐项源码复核，由本次执行助手完成，没有独立盲评。
5. 这是已知问题的整改回归，不是独立泛化验证；同时改变了内容和总览接入，不能将差异单独归因为图谱、内容组织或自动提供总览。

## 真实模型结果

| 指标（各8次） | 无主干，保留README | 旧主干 | 新主干 |
| --- | ---: | ---: | ---: |
| 平均耗时 | 44.70秒 | 60.94秒 | 45.36秒 |
| 耗时中位数 | 44.93秒 | 63.62秒 | 46.30秒 |
| 工具调用总数 | 96 | 114 | 108 |
| 工具错误数 | 0 | 1 | 2 |
| 事实检查点满足数 | 36/40 | 37/40 | 38/40 |

这是本批次的观察值，不是稳定提速比例。每题只重复两次，调用延迟和上下文缓存也有影响：同样旧基线在前一轮的耗时明显不同，不能只挑本轮旧版较慢的数据宣传收益。事实检查点不是整体正确率，附带错误另外记录在逐次复核文件中。

旧主干7/8次通过工具取得正文；新版8/8次在实际提示中提供项目总览，另有5/8次通过工具取得基线文件内容。这些次数表示资料可见和内容读取，不能直接解释为对答案有贡献。

### 具体改善与未解决问题

- 流程题：新版两次都区分业务顺序与真实状态约束；无主干两次、旧版第一次仍出现把“必须传ID”表述成“业务必须先完成”的矛盾。旧版第二次也能作出正确区分，因此改善不是新版独有的能力。
- 前置条件题：三组都识别前端硬编码与后端未核验真实状态。新版第一次、旧版第二次覆盖了另一组银行卡及还款参数检查，其余回答仍有遗漏，没有形成稳定覆盖优势。
- 优惠券题：三组均找到最终固定返回实现。新版第一次仍把折扣金额臆定为元，旧版第一次把提款金额臆定为分；修改主干没有消除无依据补充单位的问题。
- 边界题：三组都发现当前源码没有实际放款／结果通知实现。新版对“资料未覆盖、归属未知”的说明清楚，但第二次额外臆造了H5“展示返回结果”的行为，说明背景更清楚不等于所有代码描述都可靠。
- 路径错误：旧版第二次流程题1次、新版第一次边界题2次搜索了未授权的仓库共同上级目录。随后都恢复调查并回答，失败调用和耗时保留；不能将这类路径错误归因于主干内容。

## 独立待修复问题：结构化信息丢失

改写前只读核查发现，数据库有13个实体、0条关系、0个入口，流程实体仅保留查询额度一句话，而保存的原文含九步和三个入口。问题已确认，提取、校验或历史导入中的具体原因尚未定位。

本轮没有刷新或修改生产知识数据库，也没有修复图谱导入链路。因此当前问答可以读取新文档，图谱仍是原有导入结果，不能将本轮文档改写表述为图谱问题已经解决。
