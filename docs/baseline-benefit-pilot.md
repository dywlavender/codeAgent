# 业务基线收益：首次真实模型对照

日期：2026-09-04。

## 结论

本轮没有证明业务基线能明显提高当前示例的问答正确性或调查效率，也不能据此认定业务知识在真实老项目中无效。

更没有验证“结构化知识主干”的收益：本轮变量是能否读取业务基线 Markdown，数据库中的实体、关系、入口模型并未参与检索。

## 实验范围与方法

- 使用现有 `examples/channel-h5`、`examples/channel-service`、`examples/loan-middle`，包含各仓库 README。
- 实验组额外提供 `knowledge/baseline/withdraw-flow.md`；对照组不提供基线。
- 6 个问题，每题两组各运行一次，共 12 次真实模型问答。没有多次重复、显著性检验或业务专家盲评。
- 每次复制独立代码目录、生成工作区、开启新会话，不使用历史会话，不读取生产数据库。
- 使用生产运行时的 Read/Glob/Grep、dontAsk 和真实目录授权；两组提示规则相同，实际来源清单不同。
- 保留用户级配置以使用现有认证，隔离项目配置并禁用 MCP；两路并发，每次 180 秒超时、CLI 的 1 美元 API 计价预算参数。该参数不代表实际账单。
- Claude Code CLI 版本为 2.1.237，经过本机模型代理。未核实代理实际路由的上游模型，不能把这些结果宣传为某个确定模型的能力评测。
- 质量结论由本次执行助手对照源码逐题复核，不是独立人工盲评，也不是模型自评分。
- 问题和预期关键事实在运行前写入 `rubric.json`。其中“空字符串未被拒绝”作为前置条件题细节，两组都未明确展开，不能称为全项通过。

首次尝试因完全禁用设置来源而丢失认证，12 个进程均返回“Not logged in”，没有得到模型答案；这些初始化失败单独保留，不纳入以下结果。随后保留用户级认证，先执行一对，再执行其余五对。

## 逐题结果

下表时间为单次问答墙钟秒数，工具数按调用 ID 去重，包括失败调用。较短的拒答不能视为效率提升。

| 问题 | 只有代码：秒 / 工具数 | 加基线：秒 / 工具数 | 源码复核结论 |
| --- | --- | --- | --- |
| 优惠券调用链 | 71.68 / 11 | 18.86 / 3 | 对照组链路正确，但擅自补充金额单位“分”和“用于筛选”；基线组因搜索未授权上级目录而拒答 |
| 担保公司提供方与链路 | 47.16 / 10 | 63.26 / 11 | 两组都定位中台固定列表与完整链路；对照组开头“真实数据”措辞与后文“模拟数据”不一致 |
| 提款流程及系统职责 | 60.40 / 15 | 53.39 / 13 | 两组均给出九步流程、渠道透传、中台实现，并识别独立按钮及模拟数据，核心质量相近 |
| 未签合同/未授权能否拦截 | 59.87 / 14 | 49.12 / 15 | 两组都指出只查 null、不查真实性、前端写死 ID；均未明确说明空字符串同样不会被 null 条件拒绝 |
| 还款选项与提交校验 | 68.81 / 12 | 61.28 / 15 | 两组均列出正确枚举与日期、识别没有成员范围校验；基线组有“两层后端均检查”与渠道无校验的表述矛盾 |
| 是否强制执行全部查询步骤 | 23.79 / 4 | 50.45 / 13 | 对照组因搜索未授权上级目录而拒答；基线组核心结论正确，但总结把 ID 非空等同于真实完成合同/授权，存在误导 |

两组各有 5/6 次给出实质性答案，这只是回答覆盖率，不是正确率。12 次均返回运行时 `completed`，其中 2 次实际是权限拒答，说明进程正常结束不能作为任务成功指标。

## 可公平配对的效率观察

仅统计双方都给出实质性答案的四题：担保公司、流程、前置条件、还款选项。其他两题不删去，而是在上表单独列为运行失败；不混入效率平均值。

| 指标（四题合计） | 只有代码 | 加基线 |
| --- | ---: | ---: |
| 时间 | 236.24 秒 | 227.05 秒 |
| 平均每题时间 | 59.06 秒 | 56.76 秒 |
| 工具调用数 | 51 | 54 |
| 失败工具调用数 | 4 | 4 |

| CLI 返回的 cache_read_input_tokens | 186,496 | 218,048 |

加基线本轮总时间约少 3.9%，工具调用约多 5.9%。只有四对单次样本且存在缓存、并发和代理延迟影响，不能宣称存在稳定提速。缓存与非缓存 token 不能按同一价格计算，也没有足够依据报告实际节省金额。

更重要的是，有基线组只有三题出现了明确成功的基线文件 Read 调用：流程、还款选项、强制顺序。担保公司和前置条件题没有读取基线，优惠券题未完成访问。实验测到的是“可选资料”的效果，而不是“每题必用知识”的效果；不能把所有速度变化归因于知识。

## 已核实的问题

### 1. 检索范围与授权范围仍不匹配

优惠券基线组、强制顺序对照组搜索了三个仓库的共同上级 `code/`，但实际授权的是 `code/channel-h5`、`code/channel-service`、`code/loan-middle`。CLI 拒绝访问后，模型没有转向已授权的子目录，直接声称所有工具都不能读取。

因此不是三个代码仓库都不可读，也不是基线导致失败。其他运行成功读取了这些子目录。目录授权修复仍需要配合检索路径约束和失败后的正确重试，不能通过放开整个文件系统解决。

### 2. 有资料不等于回答有依据

- 优惠券代码只透传 `amount`，最终返回固定列表，没有标明金额单位，也未用金额筛选。对照组仍自行补充了这两点。
- 有基线组强制顺序题正文承认只检查字段非空，但总结又声称“必须已完成合同签订和纳税授权”。非空 ID 不能证明真实业务完成；基线并没有自动消除这种推断错误。
- 两组将 `EQUAL_INSTALLMENT` 翻译为“等额本息”，但当前示例只返回该字符串，没有计算实现支撑这一具体解释，宜保留原值或标注解释依据不足。

关键复核位置：

- `examples/channel-h5/src/pages/WithdrawApply.vue`：按钮第 5-13 行；优惠券请求第 27-29 行；合同/授权 ID 常量第 75-76 行。
- `examples/channel-service/src/main/java/demo/channel/client/LoanMiddleClient.java`：中台服务与路径第 13-20 行。
- `examples/loan-middle/src/main/java/demo/middle/service/WithdrawQueryService.java`：优惠券固定列表第 13-18 行；还款选项第 20-26 行；担保公司第 28-33 行。
- `examples/loan-middle/src/main/java/demo/middle/service/WithdrawApplicationService.java`：字段 null 校验第 19-26 行。

## 为什么还不能证明知识主干收益

1. 示例很小，类名与接口直白，README 已给出职责和入口，代码搜索本来就容易。
2. 基线九步流程与 H5 九个按钮高度重复，新增信息量有限。
3. 本轮没有真实历史决策、术语歧义、跨系统职责争议等仅靠代码难以解释的信息。
4. 尚未测结构化主干相对原始文档的额外收益，也没有过期知识实验、知识维护成本或业务专家验收。

建议先修复检索路径失败，再用真实但可脱敏的历史问题验证“代码解释不了、知识确实补充了”的部分，同时保留普通代码题与过期资料题作为对照。若只能用现有示例，结论应停留在“尚未证明增益”，不为了获得好看结果而刻意弱化对照组。
