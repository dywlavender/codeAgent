# Code Atlas 前端设计系统

这套界面是面向开发人员和业务分析人员的内部知识工作台。核心原则是“安静、可信、证据优先”：问答区保持对话感，证据区保持可核验，知识维护区保持输入、草稿和审核动作清晰。

## 视觉语言：仪器面板

界面采用“仪器面板”式视觉语言，刻意避开通用后台模板观感：

- **石墨色导航侧栏**：导航独立于内容区使用深色铬面（明暗主题一致），激活项用 2px 品牌色左指示条标记，不使用色块填充。
- **发丝线分隔取代卡片堆叠**：列表行、Evidence 条目用 1px 分隔线组织，不做圆角卡片阵列；阴影只用于浮层（对话框、下拉）。
- **小圆角**：全局圆角 3/5/7px 三档，控件 3px，面板 5px。
- **等宽字体承担元数据**：Evidence ID、路径、时长、计数、状态标签一律 `--font-code`；状态是方角等宽小标签，不是彩色药丸。
- **单一强调色**：品牌绿只出现在主操作按钮、激活状态和“证据充分”三处；代码蓝、需求琥珀、危险红仅表达来源与告警语义。
- **回答文档带编号分节**：结论、业务流程等节标题由 CSS counter 自动编号（01 · 02 …），等宽字距排印。
- **Agent 形象**：使用 `{ }` 括号符号作为标识图形，不用拟人化或闪光图标。

## 模块结构

前端按职责拆分为模块，不再使用单一入口文件：

```text
frontend/src/
├── main.jsx            # 入口：挂载 React 根节点，引入令牌与样式
├── App.jsx             # 应用外壳：hash 路由、全局状态、查询提交与中止
├── lib/
│   ├── api.js          # fetch 封装：管理员凭证注入、AbortController 支持
│   └── format.js       # 文案映射、时间格式化、Evidence 分组、会话历史构造
├── components/
│   ├── Shell.jsx       # NavRail 导航栏与 Topbar 顶栏
│   ├── ui.jsx          # Notice、EmptyState、StatusBadge、ConfirmDialog 等通用件
│   └── RunTimeline.jsx # 运行轨迹时间线（问答页与 Runs 页共用）
└── pages/
    ├── AgentPage.jsx           # 三栏工作台：历史 / 会话 / Evidence
    ├── RunsPage.jsx            # 运行记录主从视图
    ├── LibraryPage.jsx         # Code Fact / 功能知识 / Requirements 主从视图
    └── KnowledgeAdminPage.jsx  # 知识治理：待处理 / 功能知识 / 变更审核
```

路由使用 `#/agent` 形式的 hash 路由，刷新和浏览器前进后退都能保留当前页面。Code 详情通过只读接口 `/api/code/symbol/{id}` 返回源码片段和事实关系。

## 令牌分层

令牌定义在 [`frontend/src/design-tokens.css`](../frontend/src/design-tokens.css)，组件样式在 [`frontend/src/styles.css`](../frontend/src/styles.css)。禁止业务组件直接写颜色值；新增样式应优先引用语义或组件令牌。

| 层级 | 负责内容 | 示例 |
| --- | --- | --- |
| Primitive | 原始色板、间距、圆角、字体、阴影 | `--primitive-brand-500`、`--space-4` |
| Semantic | 产品语义和状态含义 | `--color-canvas`、`--color-text`、`--color-danger` |
| Component | 组件的稳定契约 | `--component-nav-active-bg`、`--component-button-primary-bg` |

深色主题只覆盖语义层，组件不需要写第二套颜色。`styles.css` 中保留的 `--accent`、`--surface` 等变量只是历史选择器的兼容别名，新的组件应使用 `--color-*` 或 `--component-*`。

## 字体规范

- 界面正文使用 `--font-body`，优先使用系统无衬线字体，中文使用苹方、思源黑体或微软雅黑回退。
- 标题使用 `--font-display`，只用于页面标题、产品名和关键结论。
- 代码符号、Evidence ID、运行时长、版本号使用 `--font-code`，保证等宽对齐。
- 字号使用 `--type-xs` 到 `--type-display`，不在组件里新增随意的字号档位。

## 图标规范

图标统一来自 `@phosphor-icons/react`，不再引入手写 SVG 或混用其他图标库。

- 导航：19px，当前项使用 `fill`，其他项使用 `regular`。
- 页面操作：15–18px，和按钮文字垂直居中。
- 空状态或欢迎状态：25–28px，只使用一个主图标。
- 图标只表达动作或来源类型，不能替代文字标签；所有无文字按钮必须提供 `aria-label` 或 `title`。

## 组件契约

| 组件 | 视觉契约 | 交互契约 |
| --- | --- | --- |
| Nav rail | 石墨铬面、右侧边界、激活项品牌色左指示条 | 用户工作区（问答、运行记录）与治理/知识库分隔；窄屏折叠为底部导航 |
| Topbar | 64px 高、项目上下文在左、知识源健康度在右 | 只承载上下文和工作台切换，不放业务提交动作 |
| Composer | Raised surface、输入聚焦有统一 focus ring、主按钮为品牌色 | Enter 发送，Shift+Enter 换行；发送期间禁用并显示加载图标 |
| Answer card | 结论、业务流程、事实、待确认分段展示 | 每轮可切换，建议追问进入下一轮，反馈动作写入服务端 |
| Evidence card | 按 CODE / BUSINESS / REQUIREMENT 分组，状态色只表示来源 | 点击展开原文或结构化引用，不在卡片中编辑知识 |
| Status badge | 方角等宽标签：`sufficient` 品牌色、`insufficient` 琥珀色、`conflict` 红色，均带同色描边 | 只描述证据状态，不使用颜色单独传递信息 |
| Generation source card | 代码、需求、业务补充使用不同来源色，卡片内只显示必要上下文 | 管理员只选择需求和补充业务语义，不直接填写来源类型或 Evidence ID |
| Draft preview | 摘要、标签、场景、规则、代码落点、数据影响按正文顺序展示 | 生成结果先进入待审核列表，不直接修改已发布知识 |
| Graph workbench | 查询结果、关系 SVG、节点检查器三栏布局，移动端纵向堆叠 | 搜索和筛选只读；点击节点查看相邻知识、来源和证据数量 |
| Admin action | 接受为主按钮，驳回为危险按钮，暂缓为次按钮 | 接受、驳回、暂缓均需要明确的当前草稿上下文 |

## 页面信息架构

1. **问答 Agent**：面向普通使用者，围绕自然语言问题返回结论和证据。
2. **运行记录**：查看可解释的 Agent 步骤、工具调用和证据状态，不展示隐藏推理。
3. **知识生成**：面向管理员，从当前代码、需求依据和业务补充生成、审核并发布功能知识。
4. **知识图谱**：面向开发人员和业务分析人员，查询功能、需求、Code Fact、标签和业务补充的关系。
5. **Code Fact / Requirements**：按来源浏览当前代码事实和需求 Digest、规则、原文证据。

这种划分把“问问题”和“维护知识”分开，减少普通使用者误触发布动作，也让管理员操作有独立的审核上下文。

## 知识生成页面

知识生成页面围绕三类输入设计，不要求开发人员理解后端来源类型：

1. **当前代码**：显示项目名称、Symbol 数量和 Code Fact 数量，默认使用最近一次同步结果。
2. **需求依据**：从已导入的 Requirement 列表勾选一个或多个需求，系统自动带入当前 Digest、规则和原文 Chunk Evidence。
3. **业务补充**：用一段自然语言补充代码和需求无法直接证明的业务语义；本次主题为可选项。

生成后，页面在“待处理”列表中展示知识草稿和来源证据。草稿预览采用功能知识正文顺序：功能定位、知识标签、业务场景、关键规则、代码落点和数据影响。冲突与证据不足单独显示在“需要确认”区域。接受操作才会进入发布状态，驳回和暂缓不会改变当前已发布版本。

如果项目配置启用了 `admin.apiTokenEnv`，知识生成页面先显示管理员凭证入口，凭证只保存在当前浏览器会话中。知识图谱页面和其他只读页面不要求该凭证。

## 知识图谱页面

知识图谱页面采用三栏工作台：

- 左栏是查询结果列表，显示节点名称、节点类型和定位信息。
- 中栏是关系视图，使用 SVG 绘制节点和关系，点击节点后高亮当前节点。
- 右栏是节点检查器，显示摘要、版本、Evidence 数量、状态和相邻知识。

顶部查询支持功能、需求、代码符号、标签和业务补充；类型筛选只改变当前只读投影，不改变底层知识。标签是功能、需求和代码之间的连接锚点，但相同标签只能形成关联候选，不能单独证明业务关系。没有证据的节点仍可被查询，但必须在检查器中显示为未建立相邻关系。
