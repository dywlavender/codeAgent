# CodeAgent 业务验收问题

## A. 业务流程理解

1. 提款申请前需要依次准备哪些信息？
2. H5 页面从进入到最终发起提款一共包含哪些业务步骤？
3. 合同签订和纳税授权是在发起提款之前还是之后？
4. 发起提款需要哪些前置选择结果？

## B. 跨仓库 / 跨系统调查

5. H5 查询额度的请求经过哪些应用，最后由哪个中台类处理？
6. H5 查询优惠券后，渠道后端调用了中台哪个接口？
7. 还款方式、还款日和担保公司分别由中台哪个 Service 提供？
8. 绑定卡查询从 H5 到中台的完整技术链路是什么？
9. 合同签订从 H5 到中台经过哪些类和接口？
10. 纳税授权从 H5 到中台经过哪些类和接口？
11. 用户点击最终提款后，从 H5 页面一直到中台提款处理 Service 的完整调用链是什么？

## C. Agent-first 验收

12. 如果只提供三个入口锚点，Agent 是否能自行找到各查询接口和 Feign 调用？
13. 回答第 11 题时，长期业务知识中是否仍然只有 Flow + Entry Anchor，而不会新增 Service/Method/代码行？
14. 修改 `WithdrawApplicationService` 内部方法后重新索引，是否无需修改业务基线即可得到最新回答？
15. 删除某个入口类名称并改名后，Agent 是否能识别 Anchor 失效并退化到实时代码搜索，而不是直接使用旧结论？

## 期望核心业务顺序

```text
额度查询
→ 优惠券查询
→ 还款方式查询
→ 还款日查询
→ 担保公司查询
→ 绑定卡查询
→ 合同签订
→ 纳税授权
→ 发起提款
```
